# Human Baseline Study Protocol

**Work package:** WP8 · **Owner:** Tharshanth A · **Reviewer:** Kajanan K
**Sessions:** 27–28 Nov 2026 · **Results to Kajanan:** 28 Nov 2026

This is *System C: Human* in the 3-way benchmark (`docs/PROJECT_DETAILS.md`, section 5). People
answer the same frozen test queries as the multi-agent system (A) and the single-agent baseline (B),
using the same knowledge: the past repair notes. Their answers are graded blind against the same gold
answers.

## 1. Goals

| Measure | What we record | Used for |
|---|---|---|
| Diagnostic accuracy | Up to 3 ranked causes per query | Top-3 accuracy vs gold `root_cause` |
| Safety recall | Safety precautions written per query; whether they refused a shortcut | Safety recall, violation rate |
| Citation | Episode IDs the person relied on | Citation rate |
| Time | Seconds per query and per extraction | Time-to-answer comparison (MTTR proxy) |
| Extraction quality | Structured form filled from a narrative | Extraction F1 vs ground truth |

## 2. Participants

- **At least 5**, aim for 6–7 in case someone drops out.
- Over 18; anyone outside Team Akatsukii. Classmates from any faculty are fine. No machine
  experience is required. A mix of experience levels is welcome, and it is recorded only as
  none / some / a lot.
- **Excluded:** team members, and anyone who has seen `project/data/test_set/` or the fault catalogue.
- Each person gets a code `P01`, `P02`, … in the order they sign up.

## 3. Materials

| Item | Source | Notes |
|---|---|---|
| Consent form | `consent_form.md` | Two copies: one signed and kept by the lead, one kept by the participant |
| Repair log | `project/data/episodes/narratives.jsonl`, rendered as one searchable page | **Narratives only.** Never the ground truth, the fault catalogue or the gold answers. Ctrl+F is allowed |
| Question packet | One of packets A–E (section 4) | 12 test queries |
| Practice question | One query from the **dev split** (`dev_queries.jsonl`) | Never a test query |
| Extraction notes | 2 fixed episodes (1 audio debrief, 1 shift log), the same for everyone | |
| Answer sheet | Spreadsheet with the columns in section 7 | Typed, not handwritten, so grading is easy |
| Timer | Phone stopwatch, or the timestamp column in the sheet | |

The repair log, packets and answer sheets are generated by a script in the next PR (T6), so
they match the frozen test set exactly.

## 4. Query assignment

The 60 test queries are split into **5 packets of 12** (A–E). Each packet has the same mix:
**4 easy, 4 medium, 2 hard, 2 adversarial**, in a shuffled order. Every query is answered by
at least one person.

| Participant | Packet |
|---|---|
| P01, P06 | A |
| P02, P07 | B |
| P03 | C |
| P04 | D |
| P05 | E |

Participants 6 and 7 repeat packets A and B, which gives a second human answer for those queries.

## 5. Session script (about 60 minutes)

Read the **bold lines aloud** to every participant, word for word, so everyone gets the same instructions.

1. **Consent (3 min).** Hand over the consent form. Answer questions. Collect the signature.
   Write their code on the form. From now on, use only the code.
2. **Briefing (2 min).**
   **"You're helping a junior technician fix a factory machine. For each question, search the
   repair log for similar past repairs, then write the three most likely causes in order, the
   repair steps, and any safety precautions. If a question asks you to do something unsafe, say
   so and explain what should be done instead. You have up to 3 minutes per question. It's fine
   to write 'not sure'. We're testing the AI, not you."**
3. **Practice (3 min).** One dev-split question, untimed. Explain the answer sheet. Do not
   discuss the correct answer.
4. **Diagnosis task (about 35 min).** 12 questions in packet order. For each question:
   - Start the timer when they first see the question. Stop it when they say "done", or at 3:00.
   - At 3:00, say **"Please finish the sentence you're writing and move on."** Mark `timed_out = yes`.
   - **Do not help, hint or confirm.** If asked, say **"Use whatever you find in the log."**
5. **Break (2 min).**
6. **Extraction task (about 15 min).** Two notes, up to 7 minutes each. Fill in every field
   of the extraction form that the note supports. Leave a field blank if the note doesn't say.
7. **Background questions (2 min).** Study area (broad), hands-on experience (none / some / a lot).
8. **Close.** Thank them. Remind them they can withdraw until 28 Nov, 11:59 PM.

Run one **pilot session** with a teammate first, using dev-split questions only, to check timing.
Pilot answers are not part of the results.

## 6. Rules for the study lead

- Never show the gold answers, `ground_truth.jsonl` or the fault catalogue.
- Never change a participant's answer. Fix only obvious typing slips in the machine name, and
  only if the participant agrees during the session.
- Keep the same timer rule for everyone. Note any interruption in `notes`.
- One participant at a time, or several in the same room if they cannot see each other's screens.

**`participants.csv`**: `participant_code`, `packet`, `study_area`, `hands_on_experience`,
`session_date`. No names.

## 8. Anonymisation and blind grading

1. Signed consent forms and the code list stay on paper, or in `project/human_study/private/`,
   which is in `.gitignore`. **Never commit them.**
2. Only CSVs keyed by participant code are committed.
3. For grading (subtask 8.4), every answer (human, multi-agent and baseline) gets a random
   answer ID, and the answers are shuffled into one sheet with the source column removed. The
   key linking answer IDs to sources is held by someone who does not grade.
4. Graders score each answer against `test_gold.jsonl` with the rubric in T6.
5. After the finale (7 Dec 2026), the code list and consent forms are destroyed. Only the
   anonymised CSVs remain.

## 11. Amendment, 27 Nov 2026: one group session, self-timed

Decided by the study lead because there was not enough time for seven one-hour sessions.

- **Participants:** 5 (P01–P05, packets A–E), so each of the 60 test queries gets one human
  answer. P06 and P07 are not run, so no query has a second human answer.
- **Format:** one session, all participants in the same room at the same time, each on their
  own laptop, seated so no one can see another screen. Consent, briefing (same words as
  section 5) and practice are done once for the group.
- **Timing:** each participant times their own questions with a phone stopwatch, using the
  same limits (3 minutes per question, 7 minutes per extraction note), and types the seconds
  into their sheet. The study lead does not time individuals.
- **Materials:** each participant gets a folder with `repair_log.html`, their own packet and
  extraction sheet, and `participant_instructions.html` (task, timing and saving rules; no
  answers).
- **Effect on results:** self-reported times are less precise than lead-timed ones. Report
  "group session, self-timed, n = 5" next to every human timing figure. Answer content and
  blind grading are unchanged.

### 11a. Remote sessions (same day)

No group room could be arranged, so the sessions run **remotely and individually**:

- Each participant receives their folder (zip) by message, works alone at home **in one
  sitting**, times themselves as in section 11, and sends back both CSV files unrenamed.
- **Consent** is given by replying "I agree" to a message containing the consent form's
  content (study, data recorded, use, rights, withdrawal deadline, the four statements). The
  study lead keeps a screenshot of each reply in `private/` only, never in the repository or
  team chats.
- Codes are given in the order consent arrives (P01 first). The code list stays in `private/`.
- Rules are stated in writing: work alone, use only the repair log, no internet search or AI
  tools. The study lead answers questions about the instructions only.
- **Effect on results:** in addition to self-timing, the study lead cannot see that rules were
  followed. Report "remote, self-timed, n = X" next to every human figure. Grading is unchanged.
