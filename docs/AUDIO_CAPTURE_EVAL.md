# Agent 1 on the audio subset (28 Nov 2026)

Agent 1 (`project/agents/a1_capture.py`, local Whisper) run on all 12 clips in
`project/data/audio` (Tharshanth's T4 subset). **All audio is synthetic**: Windows
computer voices reading synthetic narratives, 6 clean and 6 with plant noise at 15 dB SNR.
These numbers say nothing yet about real technicians, accents or plant acoustics.

**WER** is word error rate, (substitutions + deletions + insertions) / reference words.
The primary figure normalizes both texts with Whisper's own `EnglishTextNormalizer`, the
usual convention for Whisper (spelled numbers become digits; "um"/"uh" are dropped). **WER
basic** only lowercases and strips punctuation, so fillers and number formats count as
errors. **RTF** is transcription time / audio duration (below 1 is faster than real time).

## Findings

1. **Transcription works on all 12 clips**: 0 failures, 6.0% pooled WER, about 9x faster
   than real time on CPU, and every capture validates against `CaptureResult` with
   timestamped segments.
2. **15 dB plant noise did not hurt Whisper here**: noisy 5.6% vs clean 6.5%. The worst
   clip is noisy (EP-0120, 15.4%), but so is the best (EP-0307, 0.0%). Speaker, rate and
   wording matter as much as noise at this level. Six clips per group is too few to rank them.
3. **A1 flagged none of the noisy clips for review (0 of 6), and no clean ones (0 of 6).**
   A1's flags come from Whisper's own confidence (avg_logprob < -1.0, no_speech_prob > 0.6,
   compression ratio > 2.4). Whisper stayed confident on every clip: the lowest avg_logprob
   was -0.36 and the highest no_speech_prob 0.141. So A1 currently flags silence and
   garbled speech (unit-tested), **not** steady background noise. On this subset that did
   not cost accuracy, but the noisy clips are only identified by the manifest label.
4. **The errors that matter downstream are domain words, not noise**:
   - "lathe four" -> "late 4" (EP-0120): the machine type is lost unless A2 or K5
     recovers it from context.
   - "four oh alarm" -> "40 alarm" (EP-0309): the alarm code changes form.
   - "yeah" -> "yet" (several clips) and "two" -> "too": harmless for extraction.

## What this does not show

- Real recordings: the voices are synthetic and very clear.
- Noise robustness in general: only one noise type at one level (15 dB SNR).
- A tuned noise flag: no threshold was fitted on these 12 clips, because they are the
  only labelled audio. A signal-level noise estimate (e.g. an SNR check) would need its own
  development clips (`project/data/audio/make_audio.py` can generate more with another
  seed) before it is evaluated here.
