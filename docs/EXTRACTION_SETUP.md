## Implementation and handoff

Agent 2 consumes `capture_result` and emits `draft_record` using the team's shared
`LLMClient.generate_structured` interface. Pipeline A now runs CaptureAgent ->
ExtractionAgent -> end. Agent 3 and storage follow later. The A1 CLI stays capture-only.

The fetched origin/main already contained K1; K2 was fast-forwarded to that main
before development. Its PR can target main. This does not establish completion of
K1's remaining representative-sample acceptance checks.

`project/core/extraction_schemas.py` defines an additive draft contract; the shared
RepairRecord remains unchanged. Each present fact has a value and source references
(segment ID plus verbatim quote). Unknown scalars are null, missing lists are empty.
Failed attempts have separately sourced actions, outcomes and reasons; missing
outcomes/reasons remain null. Procedure list order is preserved.

Unknown evidence IDs, mismatched quotes, duplicate segment IDs and malformed output
are rejected. Timestamps are derived from A1 segments, never generated by the LLM.
Absent timestamped speech and provider failures produce traced errors with no
successful draft. Failed retries clear the previous draft.

Each draft includes model/prompt version, source path/hash, capture ID, evidence
spans with field paths, missing fields and review reasons. It always has status
draft, review_required=true and confidence=null. A3 owns confidence scoring,
semantic validation and promotion to RepairRecord while retaining provenance.
Quote membership alone does not prove that a quote supports the extracted value.
The prompt treats transcript instructions as untrusted data; resistance to prompt
injection still needs adversarial evaluation.

## Setup and offline demonstration

From the repository root in PowerShell:

```powershell
. .\scripts\Activate-FactoryMemory.ps1
python -m pip install -r project/requirements-extraction.txt
python -m pytest -q
python -m project.agents.a2_extraction --capture tests/fixtures/extraction/capture.json --fixture-output tests/fixtures/extraction/model_output.json --output logs/extraction_demo.json
```

Both fixtures are hand-authored synthetic data. The offline mode supplies the
model's expected response, testing contracts and handoffs rather than language
understanding. Its output says model=fake and includes offline_fixture_output;
completion traces carry stub=true. The diagnostic FakeLLM has no general-purpose
extraction simulation: use an explicit fixture for the demonstration.

## Live extraction

Configure the key locally, never in chat or Git. This CLI reads environment
variables, not .env files. In PowerShell 7:

```powershell
$env:OPENAI_API_KEY = Read-Host 'OpenAI API key' -MaskInput
Remove-Item Env:FACTORY_FAKE_LLM -ErrorAction SilentlyContinue
python -m project.agents.a2_extraction --capture logs/capture_result.json --output logs/extraction_draft.json
```

PRIMARY_LLM_MODEL selects the shared client's model; otherwise it uses its default.
The provider receives segment text, IDs and quality flags, not the recording or
local file path. Use only data permitted for that provider. Shared timeouts/retries
apply. On CLI failure, inspect the JSONL trace; an output from an earlier successful
run may still exist, so check the exit code. Runtime files under logs are ignored.

## Invalid-output retry (K8)

If the model returns invalid JSON or schema, or a quote that doesn't match its segment,
A2 makes **one corrective retry**: two calls in total, configurable with
`EXTRACTION_MAX_ATTEMPTS` (1-5). The retry sends the validator's message back as data,
alongside the same segments. Drafts that needed the retry carry the review reason
`extraction_retried_after_invalid_output`. Transport errors and timeouts are retried
only by the shared LLM client. See docs/HARDENING.md. The K7 development numbers (26 Nov)
were measured **before** this retry existed.
