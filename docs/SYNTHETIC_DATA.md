# Synthetic-data disclosure

**All repair data in this repository is synthetic.** None of it comes from a real plant,
real technicians, real machines, real incidents or real recordings. It was made for this
project so that Factory Memory can be built and tested without confidential factory data.

## Short version (for the README, slides and demo)

> Factory Memory is evaluated on synthetic data only. The 40 fault types, 400 repair
> episodes, 12 technicians, audio clips and 60 test queries were generated by scripts in
> this repository. No real factory, person or incident is described. Results show how the
> system behaves on this synthetic benchmark, not proof of performance in a real plant.

## What is synthetic

| Data | Where | How it was made | Size |
|---|---|---|---|
| Fault catalogue and hazards | `project/data/fault_catalogue/` | Written for this project from general maintenance knowledge by `build_catalogue.py` | 40 faults across 5 machine types, 16 hazards |
| Repair episodes | `project/data/episodes/` | `generator.py`, seed 42, from the catalogue | 400 episodes: 292 spoken-style debriefs, 108 shift logs |
| Technicians | `project/data/episodes/technicians.json` | Invented profiles T01 to T12 with speaking styles. Not real people | 12 |
| Machines and asset IDs | inside the episodes (for example `CONV-02`) | Invented. Not taken from any real site | 5 machine types |
| Audio clips | `project/data/audio/` | `make_audio.py`: Windows built-in computer voices (System.Speech) reading synthetic narratives; 6 of 12 clips have synthetic plant noise added | 12 clips, about 7 minutes |
| Test set and dev split | `project/data/test_set/` | `build_test_set.py`, seeds 2026 and 99, from the catalogue; frozen with SHA-256 | 60 test queries in 4 tiers, 20 dev queries |
| Expanded stores | `project/data/expanded/` | `expand_stores.py`, from generator ground truth | 100, 400 and 2,000 episodes |

Every file can be rebuilt byte for byte from its script and seed, except the audio, where
the speech engine output can differ slightly between Windows versions.

## What is not synthetic

- **Human baseline study (WP8).** Real volunteers answer synthetic queries under time
  limits, after signing a consent form (`project/human_study/`). Their names and consent
  forms stay offline in the git-ignored `project/human_study/private/` folder. The
  repository holds only anonymised participant codes (P01, P02, ...), answers and times.
- **Team recordings.** If team members record themselves for a demo or to check Agent 1,
  they describe synthetic repairs, not real incidents, and the recording is listed here.

## Who checked it

- The records in the expanded stores are marked `verified_by: "synthetic-generator (not
  human-reviewed)"`. They are correct by construction, because they come from generator
  ground truth, but no person reviewed each one.
- **No maintenance engineer has reviewed the fault catalogue or the repair steps.** They
  are plausible, not authoritative. Do not use them as real repair or safety guidance.
- The scripts were written with help from AI coding assistants. The tools are declared
  in [PROJECT_DETAILS.md §4.3](PROJECT_DETAILS.md#43-ai-assistants--development-tools-disclosure).

## Limitations to keep in mind when reading results

- **Easier than real data.** The episodes, test queries and gold answers all come from the
  same 40-fault catalogue, so retrieval may look better than it would on messy real
  records.
- **Cleaner speech.** Narratives include fillers, jargon and self-corrections, but real
  debriefs are less ordered. Computer voices are clearer than real technicians speaking
  over machine noise, so transcription accuracy here is likely optimistic.
- **Fixed vocabulary.** Machine names, symptoms and hazards use a small, consistent
  vocabulary. Real plants use many local names for the same thing.
- **Small human study.** The baseline uses only a few volunteers (see
  `project/human_study/protocol.md`), so differences between people and the system
  are indicative, not statistically strong.

## How to rebuild and check

```powershell
python project/data/generator.py --check
python project/data/test_set/build_test_set.py --verify
python project/data/expand_stores.py --check
```
